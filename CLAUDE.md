# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Tixup is a task/timeline ("Tix") manager. Two frontends live side by side and share one design system:

| Path | What | Status |
|---|---|---|
| `dist/` | Vanilla JS multi-page app (no bundler). This is the working product and what Tauri wraps. | Active |
| `app/` | Vite + React 19 rewrite of the timeline page. Deployed to GitHub Pages by `.github/workflows/deploy.yml` on every push to `main`. | Active port: timeline + list view, client-side auth/spaces, Apps Script backend for shared Tix |
| `src-tauri/` | Tauri 2 shell around `dist/` (`frontendDist: ../dist`). Rust commands: `check_initial_setup`, `save_configuration`, `get_configuration`. | Desktop wrapper |

Root `index.html` just redirects to `dist/guide.html` (the component gallery). Root `App.tsx` / `components/Button.tsx` are Figma Code Connect demo files, not part of either app. `test_rust_proj/` is a hello-world scratch crate.

## Commands

**Vanilla app (`dist/`)** — run from repo root:
```
npm install
npm run dev        # http-server ./dist on port 3000
```
Always use port 3000: the Google OAuth client ID in `dist/login.html` is authorized for `http://localhost:3000` only.

**React app (`app/`)**:
```
cd app
npm install
npm run dev -- --port 3000   # vite (same port-3000 rule)
npm run build
npm run lint                 # eslint (flat config, react-hooks + react-refresh)
```

There is no test suite in either app. `dist/test_drag.js` is a stale Playwright script (targets localhost:8080/test_drive.html) and is not wired to anything.

**Tauri**: config in `src-tauri/tauri.conf.json`; no `beforeBuildCommand`, it serves `dist/` as-is. tauri-cli is not a package.json dependency.

## Architecture: timeline coordinate system (shared by both apps)

Both apps use the same px-based model, defined in `dist/assets/js/tixup-constants.js` and `app/src/constants/index.js`:

- `CENTER_PX = 1_000_000` is "today" (`BASE_EPOCH`, midnight of the current day). A task's `start` is an absolute px position relative to that anchor; `width` is px.
- **Stored values are normalized to 48 px/day** (`CELL_WIDTH`). The visible zoom (`currentCellWidth` / `cellWidth`) scales them on render: `visual = CENTER_PX + (stored - CENTER_PX) / 48 * cellWidth`. Always convert with `toVisualLeft/toStoredLeft` (React) or the equivalent math in `saveData()` (vanilla); never persist visual px.
- The scroll canvas is `VIRTUAL_WIDTH = 35000` px wide and is panned with a `translateX(-panOffset)` transform. When scroll nears the edge the viewport "jumps" and the day/month header re-renders (`renderTimelineHeader` / `useTimelineScroll`). This is the source of most historical "teleport" bugs.
- `start < 300000` is treated as corrupt legacy data and reset on load.
- **Day anchoring (React app only).** Because `CENTER_PX` means "the day the app loaded", raw px values drift one day per day. Every task therefore carries `anchor: 'YYYY-MM-DD'` (the day its px were written against); `rebaseTasks()` in `app/src/utils/timeline.js` shifts `start` by the days elapsed since the anchor and re-stamps it. It runs in `useTaskStore` on local load, on every remote pull, and inside `updateTasks()` (every write). Tasks without an anchor are treated as anchored today. The vanilla `dist/` app has no such fix and still drifts.

Task shape: `{ id, title, status, type: 'parent'|'child', parentId?, start, width, anchor, assignee, dueDate, tag, collapsed, comments?, history? }`.
Statuses: `pending | inprogress | done | overdue | pause | drop` (legacy `onhold` maps to `pause`). Status drives the CSS class `marker-<status>` and row `data-status`. The status badge (`marker marker-has-icon marker-<status>`) is Figma Marker V3 (37552:6706): 24px tall, 12px text, 16px icon from `public/images/icons/marker_<status>.svg` (1.5px coloured border, glyph inside).

## Architecture: vanilla app (`dist/`)

- **No modules, load order matters.** `dist/index.html` loads `tixup-*.js` as plain scripts in dependency order (auth → constants → storage → common → filters → views → task-render → task-crud → selection → timeline-header → timeline-drag → spaces → main). Everything is a global function or lives on `window.TixupState`, `window.TixupAuth`, `window.tixupCore`.
- **The DOM is the source of truth.** `saveData()` (`tixup-storage.js`) rebuilds `TixupState.tasks` by reading rows from the DOM, then writes to localStorage. `renderAll()` clears and re-renders. If you change markup in `renderTask`, check that `saveData()` can still read it back.
- Timeline sidebar rows follow Figma "Tix Timeline" 37631:13783 (rules appended at the end of `app/src/components.css`): sidebar 459px (`SIDEBAR_WIDTH` in `TimelineView.jsx`); 40px select column (pl 16 + 24px checkbox, 16px box, 1.5px gray/500) | title (pl 8, chevron_lg_right 16px #616161 rotating down when expanded — only rendered when the Tix has sub-tix, a placeholder keeps the alignment; tix 18px / stat 20px in colors/primary, 14px title, `+` 24px #00C27B on hover; sub-tix indented 22px) | 132px status marker. Header (37635:4609) is 82px: All/Done/Overdue segment 286×32 on #f3f3f3 (24px tabs, 14px Medium, active white + 0 1px 1px shadow) with a dock_to_right icon (visual only). Timeline header = 41px "Year/ month" row (16px label, 12px ghost buttons) + 41px day row (48×28 cells, 14px #616161, today = 28px red circle, weekends red-500). Drag ghost = white card, 2px #757575, radius 8, 0 0 30px shadow. Row icons come from `public/images/icons/{tix,stat,add,chevron_lg_right,check_box_default,check_box_active}.svg` (Figma exports); `icons.css` / `components.css` reference them as `url('/images/icons/…')`, which Vite rewrites with the base in both `vite dev` and the build (a relative `../images/...` only worked in the build). The expand chevron uses the sub-tix count from the full task list, so a collapsed parent keeps its (right-pointing) chevron.
- **Three synchronized row lists** joined by `data-group="<task.id>"`: `#grid-tbody` (timeline sidebar), `#timeline-tbody` (bars), `#full-grid-tbody` (list view). `tixupCore.syncTimelineOrder()` re-orders the timeline rows to match the sidebar after drag/drop.
- `TixupCore` (`tixup-common.js`) owns Sortable.js drag-and-drop for parent/child hierarchy, the drop indicator line, expander toggling, and parent auto-resize on double-click of a bar.
- Init functions use an `_done` guard so they can be safely re-invoked (space switching calls them again).
- `debug-mutations.js` is loaded in `index.html` and logs a stack trace whenever a timeline row/bar is removed. Leave it unless removing on purpose.

**Auth & spaces** (`tixup-auth.js`, client-side only, all in localStorage):
- Keys: `tixup-user`, `tixup-active-space`, `tixup-spaces-<userId>`, `tixup-tasks-<spaceId>`, `tixup_zoom`. Legacy `tixup-tasks` is migrated into the first space by `migrateOldData()`.
- Google login uses Google Identity Services with the client ID hardcoded in `login.html`; a demo login path bypasses Google.
- After login, `login.html` redirects to `index.html` (the timeline page).

**Pages**: `index.html` (timeline/list, the main app), `dashboard.html`, `login.html`, `setup.html` (Tauri first-run config, uses `app.js` + `invoke`), `issues.html`, `guide.html` (design system gallery).

## Architecture: React app (`app/`)

- Task state lives in `useTaskStore(spaceId, { space, user })`: one localStorage list per space under `tixup-tasks-<spaceId>`. When `API_ENDPOINT` (`constants/index.js`, overridable with `VITE_API_ENDPOINT`) is set, the list is also mirrored to the Apps Script backend in `app/mail/Code.gs` (`store/remote.js`: pull on mount/focus/15 s poll, debounced push on edit, last write wins, bootstrap-publish when the backend has no document; `tixup-dirty-<spaceId>` in localStorage marks an edit that has not reached the backend yet so the first pull after a reload pushes it instead of overwriting it with the server copy). This is what lets invitees see the inviter's Tix. Every `load` also records the caller as present; the reply's `online` list (e-mails seen in the last 45 s) is exposed as `onlineEmails` and drawn as the Figma Avatar V2 "Online" dot (`public/images/header/online.svg`, bottom-right) on the TopBar / Dashboard avatars. `App.jsx` mounts `Dashboard` with `key={activeSpace.id}` so switching spaces remounts and reloads. Each task carries `boxId` (null = no box); children inherit the parent's `boxId`. "My Tasks" shows all tasks in the space, a selected box filters by `boxId`.
- `store/storage.js` holds `SCHEMA_VERSION`; on mismatch every `tixup*` key except `tixup-user` is wiped at startup (`resetLegacyStorage()` in `main.jsx`). Bump it when the stored shape changes incompatibly.
- Auth: `store/useAuth.js` keeps the user in localStorage under `tixup-user` (same key as the vanilla app) and exposes `useAuth()` via `useSyncExternalStore`. `App.jsx` renders `Login` (or `SignUp` at `#signup`) until a user exists. Google login is `utils/googleAuth.js` (GIS token popup + userinfo fetch); the client ID is in `constants/index.js` and can be overridden with `VITE_GOOGLE_CLIENT_ID`. Demo login (name + email) needs no backend. The deployed origin `https://bohemiansalt82.github.io` must be an authorized JavaScript origin for the client ID. `exitingIds`/`newIds` drive enter/exit animations.
- List view: `components/List/ListView.jsx` + `ListView.css` (Figma "List View" 37556:5816: white card with 1px #e0e0e0 border and 16px radius, columns 40px select | 300px title | 4 × 1fr, header 48px with top/bottom lines and the All/Done/Overdue segment filling its cell (pl 32 / pr 10), rows 48px border-box with #eee right lines except the select column, all rows white, title 14px, sub-tix indented 22px with a 24px stat icon, footer 56px). Same rows as the timeline plus editable Assignee (members = me + invited emails + backend `space.members`), Due Date (read-only: the last day of the Tix bar on the timeline, `getBarEndDate()` in `utils/timeline.js`), Tags (`TAGS` in `constants/index.js` = Figma Marker V3 Depart 1–8 incl. Directing, colours `lv-tag-*`, 24px / 12px). Header unfold icons sort parents (children stay under their parent); the All/Done/Overdue tabs keep a parent visible when any sub-tix matches. Task fields: `assignee: {name,email}|null`, `dueDate: 'YYYY-MM-DD'|null`, `tags: string[]`.
- Calendar view: `components/Calendar/CalendarView.jsx` + `CalendarView.css` (Figma Calendar_View 37643:4421, Calendar_View_Hover_Drag 37658:5140, Item for Calendar 37651:9139; `cv-*` classes). Month grid (Sunday first, 6 weeks) built from the same timeline px model via `calendarLayout.js` (`taskSpan()` → days from `start`/`width` at 48 px/day, `spanToPx()` back). Each block is a **parent** Tix: Type=Main Tix (no sub-tix) is a 38px title-only block, Type=Sub Tix is 60px with a 5%-black lower band (from 31px) listing the sub-tix titles; lanes are sized per week to their tallest block (`itemHeight()` in `CalendarView.jsx`). Block tint = the same colours as the timeline bars (`.timeline-bar-<status>`; keep `.cv-item-<status>` in sync). Drag a block to move it (its sub-tix bars move with it), drag the edge handles to resize, hover a day → `+` creates a Tix on that day. Every gesture calls `onCommit([{ id, start, width }])` once; `App.jsx` records a snapshot before each commit in `hooks/useUndoHistory.js` (30 steps, Cmd/Ctrl+Z / Shift+Z, active while the calendar view is shown) and restores through `useTaskStore().replaceTasks`. The month toolbar (18px month + ‹ This Month › as Button / Ghost SM) sits inside the card above the weekday header; the TopBar view tabs follow the Tab / Icon statuses (icons are CSS masks coloured by state); calendar-only icons live in `public/images/calendar/`.
- Tix detail popup: `components/Detail/TixDetailModal.jsx` + `.css` (Figma Tixup_Detail_Asigneed 37581:7211 / Tixup_Detail_Unassigned 37575:5948; `td-*` classes, same shell as MakeModal but docked right). Opened by `detailTaskId` in `App.jsx`: a plain click anywhere on a timeline-sidebar row (controls excluded; a mouse-down that travelled >4px is a drag, not a click), a click on the Tix **name** in a list-view row (`EditableTitle` `onOpen`, deferred 220 ms so a double-click still renames), or a plain click on a calendar block. Shows status (StatusBadge, editable), tags (`lv-tag-*`), assignee with "Assign to me" (unassigned) / "Accept" (assigned to someone else — reassigns to me), due date (`getBarEndDate`), the parent's sub-tix grid (2 rows + View More), and an Activity tab whose comments live on the task as `comments: [{ id, author: {name,email,picture}, text, createdAt, editedAt? }]` (edit/delete own comments, Reply prefills an @mention, Cmd/Ctrl+Enter posts). Files / Timeline tabs are placeholders. Icons in `public/images/detail/`.
- Dashboard: `components/Dashboard/DashboardView.jsx` + `DashboardView.css` (Figma Tixup_Dashboard 37700:8285; `dv-*` classes, icons in `public/images/dashboard/`), opened from the GNB "Dashboard" row (`currentView === 'dashboard'` in `App.jsx` replaces the TopBar; picking a box / My Tasks returns to the timeline). Pure stats live in `dashboardStats.js`: Overview (This Week / This Month = Tix whose bar touches the period), Keywords (word frequency over titles — the "Ai" badge is visual only), Issue status by Assignee (bar width = share of the top assignee, sortable), Issue status Distribution (SVG donuts). Header: team avatars + invite (`hooks/useInvite.js`, shared with the TopBar), Projects = boxes, Tixs = tasks, Files = 0 (not implemented), New Project = MakeModal box. The right-hand **Archive** lists every add / change recorded on a Tix, newest first (`archiveEntries()`): each task carries `history: [{ id, at, kind: 'add'|'change', changes }]`, appended by `recordHistory()` (`utils/timeline.js`) inside `useTaskStore.updateTasks()` on every local write — an `add` stores the full snapshot (title, span, status, assignee, tags, boxId), a `change` only the differing fields as `{ from, to }`; title edits within a minute of creation fold into the add; capped at 100 per task; remote pulls do not record (the other browser already did). Cards (Figma 39589:12587 unselected / 37705:12623 selected): 16px padding, radius 20; unselected = no card background with #F5F5F5 rows, selected = #E7EBE6 card with white rows (42px pills); an add shows Due date (the planned finish day, one chip), Tix to, Status (Marker V3 icon badge, row px 13 — chip rows are pl 13 / pr 6), Tags; a change shows only its rows as old › new (Due date = old finish › new finish). Day line = 3 days of last month + this month (Week = Monday weeks), month label "Mar 2025" (`monthShort()`); a dot marks days with entries (size by count); clicking a day / week tints its cards #E7EBE6 and scrolls to the first; the page itself never scrolls — the left column and the two archive panes scroll on their own. Timestamps are `dateTime()` ("2025-10-29 20:31:14"); card titles open the detail popup.
- Timeline header nav (Figma Timeline View 37635:4541 "Year/ month"): month label 16px, Day / Week / Month ghost segment (`.timeline-nav-modes`, active on #F5F5F5) driving `VIEW_PRESETS` zoom, then ‹ Today ›.
- The timeline is **imperative inside React**: `TimelineView` holds refs and `useTimelineScroll` / `useTimelineDrag` mutate `style.transform`, `style.left/width` directly for performance. Bar positions are committed back to the store via `onSaveBarPositions` after drag ends. Do not try to make drag fully declarative without reading both hooks first.
- Routing is hash-based in `App.jsx`: `#signup` → SignUp, no user → Login, otherwise `Dashboard`. `finishLogin()` in `Auth/AuthShared.jsx` clears the hash after login.
- `vite.config.js` sets `base: "/tixup/"` for GitHub Pages. Any image path written in JSX must be prefixed with `import.meta.env.BASE_URL` (see `Sidebar.jsx`); a bare `/images/...` breaks on Pages.
- Class names deliberately mirror the vanilla app so `components.css` works unchanged. Exceptions: the top bar is `components/Layout/TopBar.jsx` + `TopBar.css` (Figma "TopBar" component 39558:13539: 18px title, Tab / Icon Group view switcher incl. more_vert, 32px Filter/Sort/Hide chips, member avatars, Tix count, `+ Tix` primary button wired to create, more menu; icons in `public/images/header/`) and the left nav is `components/Layout/Gnb.jsx` + `Gnb.css` (own `gnb-*` classes, icons in `public/images/gnb/`), built from Figma Tixup-V2.0 `GNB_V5` (node 37551:4091, file 4K5p818MM8IKRboMUeDjv6): Home (Dashboard, My Task + count), Space (every space listed, the active one filled — no dropdown), Box (boxes of the active space). Dashboard / My Task / box highlight follows `view` + `activeBox`.
- Right-click rename / delete everywhere: `components/Shared/ContextMenu.jsx` (`<ContextMenu>` + `InlineName`) with `hooks/useContextMenu.js`; wired on GNB spaces (main row + dropdown) and boxes (`renameSpace` / `renameBox` / `deleteSpace` / `deleteBox`), list rows (EditableTitle `startEdit()` / `onRename(id, null)`), calendar blocks (inline title input / delete) and the timeline sidebar rows (their own older menu in `TaskRow.jsx`). Deletes ask `confirm()`; the last space cannot be deleted.
- Spaces/boxes: `store/useSpaces.js`. With `API_ENDPOINT` set the account's space list and boxes are stored on the backend as a per-e-mail profile (`profile` / `saveProfile` actions in `app/mail/Code.gs`) so the same account sees the same spaces in every browser; `useSpaceSync(user)` (mounted once in `App.jsx`) pulls on login/focus/15 s poll and pushes every change (debounced, last write wins), and `App.jsx` shows a splash until `ready` is true so a fresh browser never invents a second "My Space". localStorage (`tixup-spaces-<userId>`, `tixup-active-space`, `tixup-boxes-<spaceId>`, `tixup-active-box`) is the cache / offline fallback. `tixup-active-space` / `tixup-active-box` are browser-wide (not per user): `useSpaces()` resolves the stored id against the signed-in user's list before reading boxes, `useSpaceSync` drops a stale id on account switch, and `logout()` clears both — otherwise a new account showed the previous account's boxes. Shape: `{ id, name, visibility: "private"|"public", members: string[] }`; `members` are invited emails. A default "My Space" is created only when the account has none. Invites: `store/invites.js` builds short `#join=<spaceId>` links when the backend is configured (name/inviter resolved via `resolveInvite()`), else legacy `#invite=<base64url JSON>` links (space id/name/visibility/inviter); `App.jsx` stashes an incoming invite in sessionStorage, and once a user is signed in `joinSpace()` adds the space locally and activates it; `Login.jsx` shows an "X invited you to Y" banner while the invite is pending. Task data for the joined space then comes from the backend (see `useTaskStore` above); without an endpoint only the space identity is shared. `components/Modals/InviteModal.jsx` (Figma 39528:14464) tokenises emails via `TokenEmailInput.jsx`, blocks Invite on red (invalid) tokens, copies the link, and sends through `utils/inviteMail.js` → the Apps Script backend in `app/mail/` (same `API_ENDPOINT`; `INVITE_MAIL_ENDPOINT` is an alias), falling back to `mailto:` when unset; `public/email/invite.html` is the HTML email template (placeholders `{{SPACE_NAME}}` etc., `?space=&by=&link=` for preview). Creation goes through `components/Modals/MakeModal.jsx` (Figma 39521:11825 / 39523:13450), rendered via a portal because the GNB's `backdrop-filter` would trap `position: fixed`.

## Design system & CSS

- `tokens.css` (CSS custom properties, `--primitive-*` / semantic tokens) is exported from Figma; `design-tokens.tokens.json` at root is the source. `icons.css` defines `.icon-*` classes (data-URL SVGs, added to avoid local CORS issues). `components.css` has all component styles (`.btn`, `.marker`, `.data-grid-*`, `.timeline-*`).
- **`app/src/*.css` are copies of `dist/assets/css/*.css`.** `tokens.css` and `icons.css` are currently identical; `components.css` has diverged. When changing shared styles, decide whether both copies need the edit.
- Figma: file key `xwanZD5vsxAboXxX1t58FC` (Tixup). Code Connect is configured in `figma.config.json` (`**/*.figma.tsx`); `Marker.figma.tsx` maps the Figma Marker variants to `.marker marker-<color>`. Fonts: Pretendard via jsdelivr, Material Icons Outlined.
